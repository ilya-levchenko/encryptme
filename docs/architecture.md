# Архитектура

EncryptMe использует общий React/Vite-интерфейс и две платформенные реализации одного контракта `window.encryptMe`.

```text
React UI
   │
   ├── Electron preload/IPC ── Electron main ── локальные файлы desktop
   │
   └── Capacitor bridge ────── Web Crypto ───── Library/vault на iOS
```

## Границы платформ

- `src/App.tsx` отвечает только за состояние интерфейса и вызывает платформенный контракт.
- `electron/preload.cjs` предоставляет минимальный IPC API без доступа UI к Node.js.
- `electron/main.mjs` владеет desktop-сессией и файловой системой.
- `src/platform/` реализует тот же API для iOS и browser development.
- `src/platform/haptics.ts` добавляет единый слой тактильной отдачи; на iOS он использует нативный Capacitor Haptics.
- `ios/` содержит тонкий нативный shell, защиту app-switcher snapshot и настройки Data Protection.

## Форматы данных

Контейнер сейфа версии `2` состоит из небольшого зашифрованного индекса и независимо зашифрованных записей. Оба независимых сейфа используют общий случайный KDF-salt, но разные пароли и ключи. Новые сейфы выводят ключ через PBKDF2-HMAC-SHA-256 с 600 000 итераций, который на iOS исполняется нативным Web Crypto. После одного вывода ключа приложение проверяет оба индекса быстрым AES-GCM. Индекс подходящего сейфа расшифровывается сразу, а текст конкретной записи — только при её выборе. Каждая часть использует собственный случайный IV.

У старых профилей общий salt назначается при первом успешном входе. Активный scrypt-сейф атомарно переводится на PBKDF2. Когда пользователь впервые открывает второй сейф, он проходит такую же миграцию; дальнейшие входы с обоими паролями используют один быстрый нативный KDF-вызов.

Сейфы версии `1`, в которых дневник был зашифрован целиком, поддерживаются для чтения. После первого успешного ввода пароля приложение атомарно переводит выбранный сейф в версию `2`; при ошибке записи исходный контейнер остаётся на месте.

Резервная копия содержит профиль и оба уже зашифрованных сейфа, после чего целиком дополнительно шифруется активным паролем. Это позволяет переносить один файл между desktop и iOS без конвертации.

Browser fallback предназначен только для разработки интерфейса и хранит зашифрованные контейнеры в `localStorage`; production desktop использует Electron, а iOS — Capacitor Filesystem.

Стеклянные поверхности реализованы как progressive enhancement через системное размытие WebKit. Настоящий `UIGlassEffect` относится к нативным UIKit-контролам и не применяется напрямую к DOM внутри `WKWebView`, поэтому интерфейс сохраняет безопасный непрозрачный fallback на старых iOS.
